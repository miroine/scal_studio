# SCAL Studio

*Made by **Merouane Hamdani** for **educational purposes only**, released under the **MIT License**.*

Streamlit app for relative permeability, capillary pressure, end-point scaling, hysteresis and
simulator export, built around the Corey / LET parametrisations used by **pyscal**.
Styled after consulting-report conventions: action titles, navy / blue palette, source lines.

## Run
```bash
pip install -r requirements.txt      # pyscal is optional
streamlit run app.py
```

## What it does
| Tab | Content |
|---|---|
| Summary | Headline insight, KPIs (displacement limit, breakthrough PV, mobility ratio, Craig-type wettability read-across) |
| Relative permeability | Water-oil, gas-oil, gas-water, three-phase kro (Stone I / II, Baker) on a ternary diagram, log-axis toggle |
| Capillary pressure | Brooks-Corey, LET, van Genuchten, Skjaeveland, LET two-sided. Editable fluid configurations, Leverett conversion, J-function, saturation-height, seal capacity, MICP / Pc fitting |
| End-point scaling | Two-/three-point re-scaling; rock-type family from a permeability range (SATNUM regions with Leverett Pc scaling) |
| **Parameter advisor** | Benchmark ranges per rock / wettability profile (Craig 1971 rules, LET guidance, judgement; each value tagged with its basis), Brooks-Corey and entry-pressure starting values from k, phi and J, an assessment of your current case, an editable **low / base / high** table and a slider (0 = low, 0.5 = base, 1 = high) that interpolates the curve set. Export the **one interpolated curve** (CSV, SWOF) or the three cases as regions |
| **Uncertainty** | Monte-Carlo ensembles (end-points, curve shape, Pc multiplier): P10 / P50 / P90 kr and Pc bands, recovery and breakthrough histograms; low / mid / high realisations and a **custom percentile** realisation exported as regions |
| **Curve-set interpolation** | Blend two curve sets with a manual factor, a physical variable (salinity, polymer, WAG ratio) or the capillary number; export A-to-B regions |
| Hysteresis | Land trapping; Killough or Carlson scanning curves; Killough-type Pc scanning |
| **Lab interpretation** | JBN unsteady-state core-flood interpretation (demo with known truth, or upload PVI / NP / DP); centrifuge Pc by fitting an exact radial forward model; both can feed the sidebar case |
| Fit SCAL data | Upload CSV (Sw, krw, krow[, Pc]), detect end-points, least-squares Corey / LET fit; **deck reader** for existing Eclipse-style SWOF / SGOF / SLGOF / SWFN / SGFN / SOF3 tables (plot, download, or use a SWOF table as the measured data) |
| Animations | JavaScript canvas: Buckley-Leverett waterflood, fractional flow with Welge tangent, recovery vs PV; hysteresis loop walker |
| **Batch mode** | YAML input (edit the template or upload), engine choice (native, or pyscal when installed), curves written straight to Eclipse / CMG / MRST / CSV / JSON files with deck verification, downloaded as a ZIP. Also a command line, see below |
| **Validation** | The engine against published numbers, closed forms and an independent finite-volume solver, with expected value, result and tolerance per check |
| Export and report | Region source (base, rock types, uncertainty cases, interpolated sets); Eclipse / OPM / tNavigator / INTERSECT / Petrel, CMG IMEX/GEM, MRST, CSV, XLSX, JSON, ZIP; **deck round-trip verification**; one-click **A4 PDF summary** |

Sidebar: **presets** (water-wet and mixed-wet sandstone, oil-wet carbonate, heavy oil, gas cap, tight gas, CO2 storage, WAG; illustrative, not field data),
**save / load case** as JSON (out-of-range values are skipped and reported, never crash the app), and a **display-unit switch** (Pc: bar / psi / kPa / MPa; length: m / ft).
Inputs stay in bar and metres; plots, tables and downloads follow the display unit. Heavy computations (fits, ensembles, JBN) are cached.

Every tab opens with a **How to read this section** guide (what it shows, how to read it, what to watch for), and the **Documentation** tab holds the formulas, assumptions,
code locations and references (also in `DOCUMENTATION.md`, generated by `python docs_content.py > DOCUMENTATION.md`; a test keeps the two in sync).

## Batch mode
```bash
python scal_batch.py --template > cases.yaml          # write an example input
python scal_batch.py cases.yaml --engine native --out results
python scal_batch.py cases.yaml --engine pyscal       # needs pyscal; water-oil and gas-oil only
```
Each case is given explicitly (end-points and Corey / LET parameters), from the parameter advisor (`advisor: {profile, t}` with t between 0 = low and 1 = high),
or as an interpolation between two sets. Invalid input stops with a message naming the offending key. Output: simulator files, `summary.csv` and a `manifest.json`.
The pyscal engine builds water-oil and gas-oil curves only; the `krwmax` ramp of pyscal is not implemented in the native engine.

## Layout
- `core.py` engine (numpy/pandas/scipy only), `state_defs.py` defaults and choices, `cases.py` case-file schema and validation, `presets.py`
- `exporters.py` simulator writers, `deckcheck.py` independent deck readers/verifiers, `report.py` PDF (matplotlib), `charts.py` Plotly template, `animation.py` JS animation
- `pyscal_bridge.py` optional native-vs-pyscal cross-check and the pyscal batch engine
- `advisor.py` benchmark profiles and low / base / high cases, `batch.py` and `scal_batch.py` YAML batch mode, `validation.py` validation cases, `docs_content.py` documentation text and reading guides

For **SWOF + SGOF**, select **Three-phase (oil-water-gas)**; the advisor's direct INC download includes both tables in this mode. **Export rows per table** controls the exact download row count while preserving kr plateau endpoints. INC files include per-region model/parameter provenance and sampling details for reproducibility; see [Simulator export and verification](DOCUMENTATION.md#export).

## Notes and limits
- Benchmark ranges are generic. Tags: "Craig 1971" and "published" mark values with a literature basis, "judgement" marks typical practice; none replaces measured SCAL data.
- Validation anchors: the pyscal documentation crossover, Brooks-Corey, Land and Welge closed forms, Craig's rules, Lomeland LET guidance and an independent finite-volume waterflood solver. They show the implementation is consistent with those references, not that a field case is right.
- Native engine reproduces pyscal's Corey / LET normalisation; the cross-check on the Summary tab confirms it when pyscal is installed.
- Pc models other than pyscal's own forms are generic textbook formulations, labelled as such in the UI.
- Ensembles cover water-oil curves; JBN is valid after breakthrough and is sensitive to noise in the early points; centrifuge data constrain Pc only up to the highest inlet pressure.
- Edits to the fluid-configuration table are not stored in case files.
- Hysteresis keywords (Eclipse `EHYSTR` items, CMG `*HYSKR*`) differ by simulator version: the export provides imbibition tables and a template; check against your manual.
- Default interfacial tensions / contact angles are typical illustrative values: edit them per study.

## Capillary-pressure toolbox (v2)
- Models: Brooks-Corey, LET, van Genuchten, **Skjaeveland** (two-sided, `Pc = cw/Sw*^aw - co/So*^ao`), LET two-sided.
- **Smooth cap**: Brooks-Corey / van Genuchten reach Pc max exactly at Swirr (no flat plateau with a kink).
- Gas-oil Pc ramps from zero to the entry pressure over Sgcr (no jump at the first gas saturation).
- **Fit to data**: MICP (with closure correction) or Pc vs Sw, several models side by side, **Swirr fitted** (fixing it at the lowest
  measured Sw biases the pore-size index), R2 / RMSE table, one-click apply to the case.
- **Saturation-height function** for any in-situ fluid pair, entry height and Sw = 50 % height.
- **Seal capacity**: static column held by a caprock for CO2 / H2 / gas storage, with a safety factor.
- Pc quality checks (monotonicity, range, model consistency).
